# 2.3 SLC/MLC/TLC: More Bits, Less Reliability

## How many bits can a transistor hold?

In the previous section, we discussed two architectures, NOR and NAND. That was asking: How are billions of transistors connected on a silicon chip. Now back to a more basic physics question: How many bits can a single floating-gate transistor store? **

When we talked about the reading and writing principles of floating gate transistors earlier, we defaulted to the simplest way: electrons in the floating gate = "0", no electrons = "1". A unit only distinguishes between two states. This is called **SLC (Single-Level Cell, single-level unit)**.

But engineers weren't satisfied with that. They asked: If I precisely control the number of electrons and divide the number of electrons in the floating gate into 4 levels, 8 levels, or even 16 levels, can't I store more bits in a transistor?

This is the logic of MLC (Multi-Level Cell, 2 bit/cell), TLC (Triple-Level Cell, 3 bit/cell), QLC (Quad-Level Cell, 4 bit/cell).

But physics is not free. With every extra bit, you're using a smaller voltage window to carry the same logic information. Let's look at actual measurement data.

Chip testing equipment will do one thing for each memory cell: repeatedly program, read, and erase, and then draw a curve: **Threshold voltage distribution curve**.

The horizontal axis is the voltage (0 to 3.3V), and the vertical axis is the number of cells read at this voltage. For an SLC chip, the curve you see is like this:

```
SLC threshold voltage distribution
=======================

Number of units
  ↑
  │
  │ ┌──────┐ ┌──────┐
  │ │ │ │ │
  │ │ 1 │ │ 0 │
  │ │(Erase state) │(Programming state)
  │ │ │ │ │
  │ └──────┘ └──────┘
  └─────────────────────────────────────────────→ Voltage
         0V 1.0V 2.0V 3.3V
         ←────────── Reference voltage ───────────→
                     ~1.5V
```

Do you know what this means?

The memory unit of this SLC chip has only two states. The distribution peak of "1" (erased state) is about 1.0V, and the distribution peak of "0" (programmed state) is about 2.5V. The reference voltage in the middle is set at approximately 1.5V. When reading, the voltage lower than 1.5V is judged as "1", and the voltage higher than 1.5V is judged as "0".

There is a large open area between the two distributions. This open area is called sensing margin. In this SLC example, the sensing margin is approximately 1.0V. This means that even if the electrons in the erased state leak some and the threshold voltage drifts by 0.3V, it is still firmly in the "1" range and will not be misjudged as "0".

This is the foundation of SLC reliability: **enough fault tolerance**.

Now, the test machine switches to an MLC chip. The curve you see changes:

```
MLC threshold voltage distribution
=======================

Number of units
  ↑
  │
  │ ┌──┐ ┌──┐ ┌──┐ ┌──┐
  │ │ │ │ │ │ │ │ │
  │ │11│ │10│ │00│ │01│
  │ │ │ │ │ │ │ │ │
  │ └──┘ └──┘ └──┘ └──┘
  └─────────────────────────────────────→ Voltage
     0V 1.0V 1.8V 2.3V 3.3V
             ←─→ ←─→ ←─→
             Sensing margin ~0.3V
```

Four states: 11, 10, 00, 01. The encoding here uses Gray Code, and only one bit changes between adjacent states. This is intentional: if a cell misreads from "10" to "00", only one bit is wrong and the ECC error correction code can correct it.

The four states are squeezed into the same 3.3V voltage range. The sensing margin between each state drops from 1.0V for the SLC to about 0.3V. **Only one more bit is stored, and the fault tolerance space is compressed by 70%. **

You continue to press the button and the test machine switches to TLC mode:

```
TLC threshold voltage distribution
=======================

Number of units
  ↑
  │
  │ ┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐
  │ ││││││││││││││││
  │ │││││││││││││││││ 8 states, densely packed
  │ └┘└┘└┘└┘└┘└┘└┘└┘
  └─────────────────────────────────────→ Voltage
     0V 3.3V
     ←──────── Sensing margin ~0.15V ────────→
```

eight states. The sensing margin is further compressed to approximately 0.15V. The boundaries between the eight distributions are almost indistinguishable to the naked eye. However, the ADC (analog-to-digital converter) of the test machine must also be distinguished. The 8 levels require at least 3 bit quantization; considering noise/margin, higher resolution ADC or multiple comparisons are usually used in engineering.

If you switch to QLC, which is 16 states, the sensing margin is about 0.08V, less than one-tenth of SLC.

Do you understand now how difficult your job is?

## What can 0.2V do?

Let’s conceptualize this sensing margin problem.A NAND Flash chip powered by 3.3V has an internal charge pump (Charge Pump) circuit that can boost 3.3V to about 20V for programming and erasing operations. But when reading, it only works in the 3.3V range.

For QLC, the 16 states are evenly distributed in the voltage window of 3.3V, and the "territory" assigned to each state is:

```
3.3V ÷ 16 = about 0.206V
```

**Only 0.2V room for each state. ** And that's not all, you also have to leave a gap (guard band) between distributions to prevent the tails of two adjacent states from overlapping. The actual available window is smaller.

What is the concept of 0.2V?

The 5V output from your mobile phone charger has a fluctuation range of approximately ±0.25V, which is already a fairly stable power supply. However, the charge pump, reference voltage circuit, and sense amplifier (Sense Amplifier) ​​inside the Flash must accurately determine the presence or absence of dozens of electrons in a floating-gate transistor at a voltage of this magnitude.

One thing must be made clear here: **Flash memory cells are analog devices. **

When you write the code, `write(fd, "A", 1)` appears to be a numeric operation, and you write a certain byte. But at the physical layer, what the programming circuit is doing is: injecting a series of precisely controlled voltage pulses into the floating gate, reading the threshold voltage after each pulse, and comparing it with the target threshold. If it is not enough, add another pulse, and stop when enough.

This technology is called **Incremental Step Pulse Programming (ISPP, Incremental Step Pulse Programming)**. Its core is a series of repeated iterations:

```
ISPP algorithm pseudocode
=======================

target_vth = lookup_table[data_value] //Lookup table: the target threshold voltage corresponding to this data
current_vth = sense(cell) //Read the current threshold voltage
pulse_voltage = V_START //Start from the starting voltage

while current_vth < target_vth:
    apply_program_pulse(pulse_voltage) // Make a programming pulse
    current_vth = sense(cell) //Read back the current state
    pulse_voltage += V_STEP // Step by step increase pulse voltage
    
    if pulse_count > MAX_PULSES: // exceeds the maximum number of pulses, this unit may be broken
        mark_bad_block()
        break
```

For SLC, there are only two target voltages, and the pulses can be taken in stride, maybe 5 to 10 pulses to complete programming. For TLC, there are 8 fine target voltages, and the step size of each pulse must be extremely small (maybe a step of 0.1V), and it takes dozens or even hundreds of pulses to accurately hit the target.

**This is also why TLC's write speed is 3 to 5 times slower than SLC. ** Programming algorithms require more delicate operations to reach the exact target, and the physical speed itself does not slow down.

## Electronic Escape

Now let's talk about something even scarier: **electrons won't stay in the floating gate forever. **

The structure of the Flash memory cell is like a miniature capacitor. The floating gate is surrounded by a silicon dioxide (SiO₂) tunnel oxide layer about 8-10 nanometers thick. When programming, you use the Fowler-Nordheim tunneling effect (adding a strong electric field at both ends of the oxide layer, and the electrons directly "pass through the wall" into the floating gate) to drive the electrons into this micro-cage.

But quantum mechanics tells us: **No wall is absolutely impenetrable. **

```
Electron leakage model (simplified)
=======================

      Control Gate
      ════════════════════════
      ║ ONO dielectric layer ║
      ╠══════════════════════╣
      ║ ██ Floating Gate ██ ║ ← Electrons are trapped here
      ║ ██████████ ║ But they are slowly escaping
      ╠══════════════════════╣
      ║ Tunnel Oxide ~10nm ║ ← Weakest Link
      ╠══════════════════════╣
      ║Channel ║
      ════════════════════════
      Source (Source) Drain (Drain)


Tunneling probability T ∝ exp(-2κ·tox) ← tox = oxide layer thickness, κ is determined by the barrier height
                     ↑
                 The thinner the oxide layer, the faster it escapes.
                 10nm is not a coincidence - it is a compromise of process and physics.
                 If it's too thick, programming requires too high a voltage, and if it's too thin, all the electrons will run away.
```

The mathematical model of electron escape roughly follows the Arrhenius Equation:

```
Escape rate = A × e^(-Ea / kT)

Among them:
  Ea = activation energy (about 1.1eV, related to the quality of the oxide layer and trap density)
  k = Boltzmann constant
  T = absolute temperature (Kelvin)
```

Note that `T` is in the denominator of the exponent. **The higher the temperature, the faster the escape. **

For SLC, this problem is not fatal. Assume that the SLC's "1" state threshold voltage is approximately 1.0V, the "0" state is approximately 2.5V, and the reference voltage is 1.5V. Even if the floating gate leaks 0.4V of charge, "1" may become 1.4V when read out, but it is still lower than the 1.5V reference line and is still judged as "1". No problem.

For TLC, the sensing margin is only 0.15V. Leak 0.1V and you've crossed the border.

```
The impact of leakage on different cell types
=======================

SLC:
  ┌──────────────┐ ┌──────────────┐
  │ "1" status │ ←─0.4V─→ │ "0" status │
  │ (0.5~1.5V) │ Safety margin │ (1.5~3.0V) │
  └──────────────┘ └──────────────┘
                      ↑
                  Reference voltage=1.5V
  After leaking 0.4V: 1.0V→1.4V, still judged as "1" ✓ Safe


TLC:
  ┌──────┐┌─────┐┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐
  │State 0 ││State 1 ││State 2 ││State 3 ││State 4 ││State 5 ││State 6 ││State 7 │
  └──────┘└─────┘└──────┘└─────┘└──────┘└──────┘└──────┘└──────┘
           ←─0.15V→
  After leaking 0.1V: cells in state 3 may be misread as state 4 ✗ Bit error!
```

This is the core contradiction: **The more bits each unit stores, the smaller the voltage window of a single state, and the lower the tolerance for charge leakage. **You either accept the shorter save time or find a way to correct the error.

## ECC: The math that wipes your butt

The so-called "finding ways to correct errors" is **Error Correction Code (ECC, Error Correction Code)**.The commercialization of TLC and QLC relies on mathematics, because physically we have hit the wall of quantum tunneling and can no longer rely on physics to reduce charge leakage. Before the data is written in, redundant information is appended; when it is read out, this redundant information is used to detect and correct errors.

SLC products usually require only simple 1-bit error correction (Hamming code). MLC requires BCH code (Bose-Chaudhuri-Hocquenghem), which can correct multiple bit errors in each codeword. TLC and QLC require LDPC (Low-Density Parity-Check), a soft-decision decoding algorithm that reads "how likely is this bit to be 0 and how likely is it to be 1", and then corrects the error through iterative probabilistic inference.

```
Flash error correction technology evolution
=======================

SLC (2 states)
  │
  ├── ECC requirements: 1-bit error correction/512B
  │ Technology: Hamming Code
  │ Overhead: ~13 bit/512B (~0.3%)
  │
MLC (4 states)
  │
  ├── ECC requirements: 4~8 bit error correction/512B
  │ Technology: BCH code (Bose-Chaudhuri-Hocquenghem)
  │ Overhead: ~60 bit/512B (~1.5%)
  │
TLC (8 states)
  │
  ├── ECC requirements: 40+ bit error correction/1KB
  │ Technology: LDPC (Low-Density Parity-Check)
  │ Overhead: ~10% of storage space
  │
QLC (16 states)
  │
  ├── ECC requirements: 100+ bit error correction/2KB
  │ Technology: LDPC + multiple rereads + machine learning calibration
  │ Overhead: ~15%~20% of storage space
  │
PLC (32 states) ← Laboratory stage
  │
  └── The industry is trying, but the current yield is extremely low.
      Even if it does, write speeds can be hopelessly slow.
```

The overhead of ECC is not free. BCH codes occupy about 1.5% of the additional storage space, LDPC codes occupy 10% or more, and ECC, OP and bad block management all occupy the original capacity.

And ECC is not a panacea. LDPC soft-decision decoding requires reading the same unit multiple times (using different reference voltages), reading multiple samples, and then making probabilistic inferences. This process is called **read retry**. On a consumer-grade SSD, you may not feel it because the controller does all this quietly in the background, taking only microseconds. But if there are too many errors, LDPC cannot save it. The controller will mark the block as a bad block, migrate the data away, and never use it again.

**This is what you're buying when you buy a "cheap TLC SSD": smarter math to make up for the compromises in physical media. **

## Temperature experiment at 85°C

In 2020, a reliability white paper from a leading NAND manufacturer disclosed such a set of data:

At room temperature (25°C), a brand new TLC NAND Flash has a data retention time of approximately 1 year after undergoing 3,000 P/E cycles. But note that this is data under cold power-off storage conditions. When the chip is not powered on, the electrons in the floating gate can only be blocked by the 10-nanometer oxide layer.

Now raise the temperature to 85°C, which is a common operating temperature for automotive ECUs in the engine compartment.

For the same chip, after the same 3,000 P/E cycles, the data retention time plummeted from 1 year to **less than 1 month**.

To 125°C, which is the high-temperature certification temperature for some extreme industrial applications and automotive grades, storage times may drop to a few days.

```
Effect of temperature on data retention time (TLC NAND, typical)
=======================

Operating temperature P/E=0 (new) P/E=3000 (mid-life) P/E=5000 (end of life)
────────────────────────────────────────────────────────
25°C 10 years 1 year 3 months
55°C 3 years 3 months 2 weeks
85°C 1 year 1 month 3 days
125°C 3 months 1 week 1 day

Note: The above is an order of magnitude estimate, and the specific values vary by manufacturer and process node.
     But the trend is certain: Q10≈2 is commonly used to estimate empirically; the actual rate is determined by the activation energy and process.
```

This answers why your car navigation system’s SD card inexplicably loses data after being exposed to the sun in the summer. It also answers why the automotive industry almost completely rejects TLC/QLC NAND as the main storage medium for ECUs.

## Temperature: the accelerator of physics

The 85°C experiment is often used to fit the retention model; empirically, Q10≈2 is commonly used to estimate, and the actual rate is determined by the activation energy and process. SLC retention time at 125°C is typically measured in months/years. For TLC, the sensing margin is only 0.15V, and data can start to become erroneous within days at the same temperature.

This is an inevitable conclusion of physics that goes beyond engineering preference: **For every extra bit, temperature pushes you up a notch in entropy. ** When the consequence of data corruption is brake failure rather than loss of photos, you can only choose the path with the largest sensing margin.

Many safety-critical ECUs use SLC NOR; infotainment/maps, etc. will also use NAND/eMMC/UFS because SLC's sensing margin can withstand 125°C in the engine compartment (the architectural advantage is a topic in 2.2).

## Read interference: If you don’t write, the data will be destroyed.

There is another issue that is easily overlooked: Read Disturb.

You may be thinking: I only read and don’t write, so the data won’t be corrupted, right?

No.When you read a Flash memory cell, you need to apply a read voltage (usually about 5V) to the control gate and sense the current between the source and drain. Although this read voltage is much lower than the programming voltage (~20V), it does affect other cells on the same word line.

In NAND Flash, all cells in a block share word lines and bit lines. When reading a page, add Vread to the selected word line, and add Vpass to other word lines in the same block; the unselected pages are disturbed. Repeated reading, such as your driving recorder repeatedly playing back video files, will cause those cells that are "only read" to be slowly soft programmed, and the threshold voltage will move up slightly.

```
NAND read disturb mechanism
=======================

        Bit Line 0 Bit Line 1 Bit Line 2 ... Bit Line N
         │ │ │ │
    ─────┼─────────┼─────────┼──────────────┼── Word line 0 (select, add read voltage ~5V)
         │ │ │ │
    ─────┼─────────┼─────────┼──────────────┼── Word Line 1 (not selected, but electric field is also felt)
         │ ↑disturbed ↑disturbed ↑disturbed │
    ─────┼─────────┼─────────┼───────────────┼── Word line 2 (same as above)
         │ │ │ │


Repeatedly reading different bit lines on word line 0
       ↓
All cells on word line 1 and word line 2
The threshold voltage slowly moves up
       ↓
Cells in erased state ("1")
The voltage rises across the reference line
Misread as programming state ("0")
       ↓
Bit errors caused by read disturb
```

NOR Flash is much better than NAND in terms of read disturbance. There are three reasons: First, the read voltage of NOR is usually lower; the Vread of the selected word line of NAND is about 0-3V, and the Vpass of the unselected word line is about 6-8V; second, the cell structure of NOR does not accumulate the "soft programming" effect like the NAND series chain; third, when NOR does XIP, the read operations are scattered at different addresses, and reading the same page in NAND will repeatedly interfere with neighboring cells sharing the same word line. This is another reason why cars prefer NOR. Most of the operations of the ECU are to read firmware code (XIP, Execute-In-Place). Read operations account for a very high proportion, and resistance to read interference is crucial.

## Library

Before I say goodbye to this section, I want to leave you with a metaphor, a metaphor that you will never forget.

Imagine you are organizing a bookshelf:

**SLC = thick wood bookshelf. ** Each shelf is either full of books ("1") or empty ("0"). You can see clearly from a distance: there is a book in this square, and there is no book in that square. No ruler or precision instruments are needed, the naked eye is enough. If someone secretly takes away half of the book, you won't be able to tell it at all, because the book is thick enough, and if half of the book is taken away, the remaining half is still "there is a book". **This is SLC: two states, with a huge margin, visible to the naked eye. **

**MLC = Membrane Bookshelf. ** Each shelf has four states: full shelf, half shelf, three books, and empty shelf. You need to get closer to tell the difference. In low light, half a shelf might look like three books. You need a ruler. **Sensing margin is the basis for your judgment in fuzzy reality. **

**TLC = cardboard bookshelf. ** There are eight possible spine thicknesses for each shelf. You can't tell the difference with the naked eye, you need a vernier caliper. You go from judging "is there a book" to measuring "how thick is the spine?" Moreover, the cardboard will slowly become damp and soft over time (charge leakage). You may measure it at 3.5mm today, and it will become 3.1mm three months later, and 3.0mm is the boundary. **What you do has changed from "keeping books" to precision measurement. **

**QLC = Do you still want to stack up? **Sixteen spine thicknesses are available for each shelf. Your calipers must be lab grade. Every measurement is accompanied by inevitable errors. Moreover, the bookshelf is constantly deforming due to moisture, and the speed of deformation depends on the temperature, humidity, and the last time you adjusted it...** What you manage is already a physical measurement laboratory. **

Do you understand the core proposition?

**Every time you add a bit, you are using a more fragile physical reality to carry the same logical information. ** You can use math (ECC) to tinker with physics, but math has its limits. Shannon's theorem is a law of physics.

If one day, someone tells you, "We have made an eight-layer cell (OLC), each cell stores 8 bits," you don't need to read the white paper. You just need to ask him one question:

**"What is the sensing margin?"**

If he hesitates, the answer is: "Already below the thermal noise level."

## PLC and 3D NAND: A Dance at the Limits of PhysicsAt this point, you may ask: Since QLC has already packed 16 states, and the sensing margin is only 0.08V, why is the industry still promoting PLC (Penta-Level Cell, five-layer unit, 32 states)?

The answer is: **They do not solve the problem in the same dimension. **

Traditional planar NAND (2D NAND) can no longer proceed at about the 15nm process node. The photolithography accuracy is approaching the quantum limit, and the crosstalk (cell-to-cell interference) between cells is too large to be ignored. A change in the programming state of one cell will affect adjacent cells through parasitic capacitive coupling, causing "neighbor interference." It's like a row of people crowded in a narrow alley. If one person moves, the people on both sides of him will feel it.

So the industry turned to **3D NAND**, changing the storage units from planar arrangement to vertical stacking, building them up layer by layer like building a skyscraper.

```
2D NAND → Dimension jump of 3D NAND
=======================

2D NAND (planar):
  ┌──┬──┬──┬──┬──┐ ← All units are on the same plane
  │ │ │ │ │ │ As the manufacturing process shrinks, the unit spacing becomes smaller and smaller
  ├──┼──┼──┼──┼──┤ Crosstalk intensifies and sensing margin deteriorates
  │ │ │ │ │ │
  └──┴──┴──┴──┴──┘

3D NAND (vertical):
         ↑
    ┌───┴───┐
    │ Layer N│ ← Layer N
    ├───────┤
    │ Layer │ ← ...
    │ ... │
    ├───────┤
    │ Layer 3│ ← Layer 3
    ├───────┤
    │ Layer 2│ ← Layer 2
    ├───────┤
    │ Layer 1│ ← Layer 1 (on substrate)
    └───────┘
         ↓

Advantages: Each unit can be made larger (because the units are spaced larger on the same layer),
      The sensing margin is better than that of 2D with the same density.
      Use large size units + vertical stacking in exchange for increased density.
```

3D NAND has currently been stacked to 232 layers or even higher (Micron will mass produce 232 layers in 2023, and Samsung will advance to more than 300 layers). The connection between each layer is through a vertically penetrating "channel hole", which is a terrifying etching process with an aspect ratio of over 100:1.

The 3D NAND unit uses a structure called Charge Trap Flash (CTF). It traps electrons in the silicon nitride (Si₃N₄) layer, like a trap array. The benefit of CTF is that the charge is fixed in the trap and does not move freely like a floating gate, so the crosstalk between adjacent cells is smaller and the sensing margin can be made wider.

But even with 3D NAND and CTF, the laws of physics still punish multi-bit storage. The P/E life of TLC 3D NAND is typically 3 to 5 times higher than that of QLC 3D NAND. Moreover, as the number of layers increases, there will be process deviations between upper-layer units and lower-layer units, resulting in inconsistent storage characteristics, which will further compress the sensing margin.

The industry is caught in an interesting contradiction: **NAND manufacturers are frantically pursuing more bits per unit to reduce costs per GB, but Flash file system engineers are forced to use stronger ECC and more complex FTL to cover up the unreliability of these bits. ** In an offensive and defensive battle, both sides use the physical limit as the frame of reference, trying to squeeze out another drop of water from the stone.

Our production system, on the other hand, uses SLC NOR, which has small capacity and high cost, but is reliable. There is a value judgment behind this choice: **When the consequences of data corruption are brake failure rather than loss of photos, reliability takes precedence over all else. **

## Entropy increase is the eternal opponent of storage

From the perspective of physics, any physical system containing information is heading towards chaos. This is a direct corollary of the second law of thermodynamics.

When you program an SLC cell, you use a strong electric field to drive thousands of electrons into the floating gate. This is a low-entropy state: the electrons are precisely confined to a small space. Information is coded as "0".

But as soon as you let go, the programming pulse stops and the entropy increase begins. Electrons slowly leak through the traps in the oxide layer, and the number of electrons in the floating gate drops from thousands to hundreds or dozens. The threshold voltage drifts from a clear "0" state to a fuzzy "1" state. Eventually, your "0" becomes a "1" and the information is erased.

**It is erased by time. is erased by entropy. **

When you program a TLC cell into one of 8 states, you are fighting greater entropy-increasing pressure. Because the voltage window of this state is only one-eighth that of SLC, any slight physical perturbation may change one state into another. You are like drawing a thin line on the beach, and it disappears as soon as the waves come.

ECC is your tool to combat entropy, using redundant information to correct physical errors. But ECC itself also consumes space (meaning more physical units), and more physical units are also affected by entropy increase. This is a recursive paradox: the very tools that combat entropy increase themselves.**This is the most profound philosophical proposition of storage: you can never completely defeat entropy. You can only delay it. The entire wisdom of Flash file system engineering is to allow information to live longer than it "naturally should" within limited time and limited resources. **

---

Entropy is always an inequality.
