# 2.5 From Package to Engine Bay: The Final Journey of a Flash Chip

## Stage 1: Encapsulation - put armor on the naked die

When a Flash die comes out of the fab, it's just a piece of bare silicon a few millimeters square. It is fragile, afraid of moisture, static electricity and mechanical shock. Packaging is the only way for it to change from "laboratory sample" to "industrial component".

**Cut.** A blue film is attached to the back of the wafer, and the diamond blade of the dicing saw cuts along the cutting street at a speed of 30,000 revolutions per minute. The width of the incision is about tens of microns. Chips and cracks are yield killers.

**Solid crystal.** The qualified die is picked up from the blue film by the pick-up head and placed on the lead frame. A layer of epoxy resin filled with silver powder is applied in the middle, which is also responsible for bonding and thermal conductivity.

**Wire bonding.** A bonder uses ultrasonic waves and pressure to connect gold wires about 25 microns in diameter from the die pads to the pins. A typical SOIC-8 packaged NOR Flash has 8 pins: VCC, GND, CS#, SCK, SI, SO, WP#, HOLD#.

```
Flash packaging structure (SOIC-8 as an example)
=======================

        ┌──────────────────────────┐
        │ Plastic sealing compound (epoxy resin) │
        │ ┌───────────────────┐ │
        │ │ │ │
        │ │ Flash Die │ │
        │ │ (2mm × 2mm) │ │
        │ │ │ │
        │ └───┬──┬──┬──┬──┬──┘ │
        │ │ │ │ │ │ │
        │ Bonding wire (gold/copper, Φ25μm) │
        │ │ │ │ │ │ │
        └──────┼──┼──┼──┼──┼──────┘
               │ │ │ │ │
    ═══════════╪══╪══╪══╪══╪══════ Pin pad (PCB side)
               1 2 3 4 5 ...
```

**Plastic sealed.** The mold is injected with heated epoxy resin (~175°C, ~1000psi) to wrap the die and gold wire. After curing, it is laser marked to indicate the model number, batch number and pin 1.

**Final test.** The packaged chip should be run through a complete test: DC parameters, AC parameters, full functional coverage, -40°C cold test / +25°C normal temperature / +85°C hot test (industrial grade) or +125°C (automotive grade). The tested chips are packed in tape and reel and ready to be sent to the circuit board factory.

## Stage 2: Mounting to ECU - chip into the car

**SMT patch.** The placement machine uses a vacuum nozzle to accurately place the chip on the PCB pad at a speed of more than 10 pieces per second (the solder paste has been printed in place through the stencil). The placement deviation of SOIC-8 packages must be controlled within ±0.1mm.

**Reflow soldering.** PCB enters the tunnel furnace with different temperature zones:

```
Reflow soldering temperature profile
=======================

Temperature (°C)
  ↑
 250│ ┌────┐
    │ / \
 200│ / \
    │ ┌───────────/ \────
 150│/
    │/
 100│/
    │/
  25└────────────────────────────────→ Time
      Preheat, keep warm, reflow, cool
      ~120s ~90s ~60s ~60s


Peak temperature: 240~250°C (lead-free solder paste)
Time above liquidus line: 60~90 seconds
```

The peak temperature of 240-250°C lasts about 60 seconds, and the solder paste melts to form a reliable solder joint. To prevent the tombstone effect, the melting time of the solder at both ends of the component is inconsistent, and the tension imbalance causes one end to stand up like a tombstone.

**ICT testing + burning.** ICT bed of needles checks solder connectivity. Then ISP (online programming) writes the bootloader or initial firmware into Flash through the MCU's SPI interface. Automotive ECUs generally choose online burning or offline burning followed by verification, and the data cannot be wrong.

## Stage 3: Run – The moment you step on the gas pedal

Now this NOR Flash is quietly welded to the ECU, waiting in the engine compartment for the MCU to be powered on.

**MCU is powered on.** The PMIC converts the 12V car battery voltage to 3.3V for the VCC pin. The internal POR circuit detects VCC rising to the threshold and releases reset. After a few hundred microseconds, Flash is ready.

**Flash driver initialization.** The MCU's SPI controller sends `0x9F` (RDID), and the Flash replies with the manufacturer ID + memory type + capacity. After the driver confirms its identity, it configures the SPI clock (usually 50-100MHz) and mode.

```
SPI Flash communication timing (FAST_READ command)
=======================

CS# ‾‾\_______________________________________________/‾‾‾‾‾‾‾
         Command address dummy period data
SCK __/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\
      0x0B A23...A0 X X X X X X X X D7 D6 D5 D4 D3 D2 D1 D0

SI ──＜Command＞─────＜24-bit address＞─────────────────────────
SO ───────────────────────────────＜Read data────────────


Typical speed: SCK = 100MHz → 10ns per clock
Data output rate: 100Mbps (12.5 MB/s)
```

**File system mounting.** File system initialization on MCU, reading Superblock, checking magic number, version number, CRC32. Backup Superblock ensures that if one copy becomes corrupted, another copy is available. Everything is OK → The file system is ready and the application can start reading and writing files.

**Runtime: the full link of a read operation.**

```
The physical journey of a file read
======================

Application layer: read("calibration.dat", buf, 128, 0)
    ↓
File system layer: Find file entries, calculate logical block number → physical block number
    ↓
Flash driver layer: prepare SPI command sequence (FAST_READ + 24-bit address)
    ↓
MCAL layer: Call the SPI driver to send commands
    ↓
Inside the NOR Flash chip:
    - The address decoder selects the corresponding sector and word line
    - Sense amplifier reads threshold voltage
    - Compare with the reference voltage → judge as "1" or "0"
    - Shift register → SO pin output
    ↓
DMA completion interrupt → data in MCU’s SRAM
    ↓
File system layer: copy to user buf
    ↓
Application layer: buf has the correct 128-byte data
```

The entire process takes about tens of microseconds at 100MHz SPI. People can't feel it at all. **Dangerous moment when engine starts/stops.** The starter motor draws several hundred amps from the 12V battery during startup, and the battery voltage may drop to 6V momentarily. Flash's VCC dropped accordingly. If VCC falls below the POR threshold, the Flash is reset, the ongoing erase/program operation is interrupted, and the sector data may be partially corrupted. This is why embedded file systems must consider **power-off safety**: Copy-on-Write, log structured metadata, CRC checks, and build reliability layer by layer in an unreliable physical world.

## Interpretation of key data sheets: Cypress S25FL256S NOR Flash

| Parameter | Value | What it means |
|------|------|-----------|
| Capacity | 256Mb (32MB) | ECU firmware (2-8MB) + calibration data (tens of KB) is more than enough |
| Sector size | 4KB/64KB/256KB hybrid | Small sectors store calibration data, large sectors store firmware |
| Programming time (256B page) | 1.5ms | Writing 128 bytes of calibration data takes about 1ms |
| Erase time (4KB sector) | 50ms | Modify a calibration data block about 50 ms |
| Erase time (64KB block) | 256ms | Firmware upgrade scenario |
| P/E Lifetime | 100,000 times | 10 erases per day, theoretical life of 27 years |
| Data retention | 20 years (25°C typical) | Meets automotive 15 year+ requirements |
| Operating temperature | -40°C ~ +125°C (AEC-Q100 Grade 1) | Full coverage from Mohe in winter to Turpan in summer |
| SPI clock | Up to 133MHz (DDR) | Read throughput up to 66MB/s (4-wire parallel) |
| Standby current | ~5μA | Almost no power consumption after flameout |

## Millisecond process from code to electronics

You wrote `write_file("calibration", data_buf, 128)`. After you press Enter on this line of code, the instructions go through the Cortex-R5 pipeline, AXI bus, SPI FIFO, PCB traces, chip pin gold wires, the charge pump inside the Flash, and the F-N tunneling effect. Eventually, about a few thousand electrons are trapped in the polysilicon layer of the floating gate, and the threshold voltage accurately drifts from the "1" state to the "0" state.

**The data you write turns into the precise positions of dozens of electrons in the physical world in milliseconds.**

This is an abstract edifice built by thousands of engineers: from materials scientists who study single crystal growth, to physicists who design lithography machine lenses, to embedded engineers who write Flash drivers. Each level of abstraction promises the next level “you don’t have to care what’s going on below me.” But behind every layer of promise are decades of physical research and engineering practice.

The file system you will implement later in this book is the middle layer of this building. Yours below is the SPI Flash instruction sequence and yours above is `write("file.txt", data, size)`. You must understand the physical truth below to provide reliable commitments to higher-ups.

**Engineering is to build "reliability" layer by layer on top of "unreliability" one after another.**
