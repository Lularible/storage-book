# 5.14 The Self-Test Program: Run Through Every Operation

## No hardware, no cross-compilation, no target board

You are on an x86_64 Linux laptop, with only gcc and the terminal in front of you.

One line command:

```bash
make && make test
```

Then the terminal scrolls through the output of 12 test cases, and finally prints a line:

```
  RESULTS: 18 / 18 tests passed
```

These ~474 lines of test code mainly verify the normal path: double SB mount/remount, CoW replacement, CRC32 check, event loop, read offset clipping, append's RMW, and delete's block release. It does not inject negative scenarios such as power outage, SB/Log corruption, or CRC failure.

It is not about burning firmware on an embedded development board. It is not a link that requires a JTAG debugger. It is a C program that runs directly on your computer, with zero dependencies and only requires libc and a C11 compiler. But its architecture, its state machine, and its data structure are cast from the same mold as the engineering version.


---

## Testing framework: minimalism in 18 lines

```c
#include "knotfs.h"
#include <stdio.h>
#include <string.h>

static int ok_ct = 0;
static int all_ct = 0;

#define T(name) do { printf("  [%s] ", name); all_ct++; } while(0)
#define OK() do { printf("OK\n"); ok_ct++; } while(0)
#define FAIL(f, ...) printf("FAIL: " f "\n", ##__VA_ARGS__)
```

Three macros support the entire testing framework. `T(name)` declares a test point, prints the name and increments the count. `OK()` passed the test. `FAIL(f, ...)` test fails and prints diagnostic information. There is no assert macro, no setjmp/longjmp exception handling, and no test discovery mechanism. It is the simplest "C function call chain".

This is very suitable for testing scenarios of embedded file systems. The essence of testing is to "perform operations and check results." The API returns 0 to indicate success (entry into the queue is successful), and `drive()` returns 0 to indicate that the operation is completed. The intermediate state of the file system is in memory, and `sb.nodes[]` and `sb.free_map` can be directly checked.


---

## drive(): tautology of event loop

```c
static int drive(void) {
  int t = 0;
  while (knotfs_run()) {
    if (++t % 15 == 0)
      printf("    tick %d...\n", t);
  }
  if (t > 0 && t % 15 != 0)
    printf("    tick %d... done\n", t);
  return knotfs_get_result();
}
```

`drive()` is not a special function. It is `while (knotfs_run());` with a progress print added (one dot every 15 ticks). It turns an asynchronous event loop into a synchronous wait, which is how you "wait for an operation to complete" when your code doesn't have an OS.

`knotfs_get_result()` returns `cur.result`, which is the return value of the last completed request. 0 is success, negative value is error code.


---

## power_cycle(): Simulate MCU power failure and restart

```c
static void power_cycle(void) {
  knotfs_init(); /* clears runtime state, does NOT erase flash */
}
```

All runtime status of KnotFS, `sb`, `sb_alt`, `fdev`, `q[]`, `cur`, `mounted`... are all cleared in `knotfs_init()`. However, the `flash[]` array is not affected. It simulates a NOR Flash chip and the data is retained after power failure. This is the whole secret of "simulating MCU power off": **Clear RAM and keep Flash. **

On real hardware, the RAM must be cleared after the MCU is reset, and the Flash will be automatically maintained. The test code uses the same mechanism to simulate this process. There is no need to actually unplug the power supply. One line of `power_cycle()` is enough.

## Test structure: 12 test functions, 18 checkpoints

The entire test program (`main` function) is a sequential call chain:

```c
int main(void)
{
    printf("\n");
    printf("  _  __            _   _____ ____  \n");
    printf(" | |/ /_ __   ___ | |_|  ___/ ___| \n");
    printf(" | ' /| '_ \\ / _ \\| __| |_  \\___ \\ \n");
    printf(" | . \\| | | | (_) | |_|  _|  ___) |\n");
    printf(" |_|\\_\\_| |_|\\___/ \\__|_|   |____/ \n");
    printf("\n");
    printf("  Teaching File System — Async + Log-Structured + Power-Loss Safe\n");
    printf("  Simulated NOR Flash: %u KB\n\n",
           KNOTFS_BLOCK_COUNT * KNOTFS_BLOCK_SIZE / 1024);

    knotfs_init();  /* first-ever boot: flash initialised to 0xFF */

    t1_format_and_mount();
    t2_write_and_read();
    t3_large_file();
    t4_partial_read();
    t5_overwrite();
    t6_append();
    t7_list();
    t8_delete();
    t9_nonexistent();
    t10_stats();
    t11_power_loss();
    t12_format_and_remount();

    printf("\n============================================================\n");
    printf("  RESULTS: %d / %d tests passed\n", ok_ct, all_ct);
    printf("============================================================\n\n");
    return (ok_ct == all_ct) ? 0 : 1;
}
```

**Test 1: format_and_mount**, the most basic life cycle.

```c
T("format");
int r = knotfs_format();
if (r) { FAIL("enqueue=%d", r); return; }
r = drive();
if (r == 0) OK(); else { FAIL("result=%d", r); return; }

T("mount");
r = knotfs_mount();
if (r) { FAIL("enqueue=%d", r); return; }
r = drive();
if (r == 0 && knotfs_is_mounted()) OK(); else { FAIL("result=%d", r); return; }

T("stats");
uint32_t tot, fre;
knotfs_stats(&tot, &fre);
drive();
if (fre == KNOTFS_DATA_BLKS) OK(); else FAIL("free=%u expected=%u", fre, KNOTFS_DATA_BLKS);
```

All 14 data blocks after format are free. This test verified: erase all 16 blocks → write double SB → mount recognizes valid SB → free_bitmap shows all data blocks FREE.

**Test 2: write_and_read**, read and write closed loop.

```c
{ const char *s = "Hello, KnotFS!";  uint32_t n = (uint32_t)strlen(s);
  T("write 14B");
  if (knotfs_write("greet.txt", s, n)) { FAIL("enqueue"); return; }
  if (drive()) { FAIL("result"); return; } OK(); }

{ char b[32];  uint32_t br;
  T("read back");
  if (knotfs_read("greet.txt", b, sizeof(b), 0, &br)) { FAIL("enqueue"); return; }
  if (drive()) { FAIL("result"); return; }
  if (br == 14 && !memcmp(b, "Hello, KnotFS!", 14)) OK();
  else FAIL("got='%.14s' len=%u", b, br); }
```

14 bytes, less than 4% of a block, are stored in Flash through the complete CoW write process, and then read back through the offset calculation of the read state machine and tmp copy. `br == 14 && !memcmp(b, "Hello, KnotFS!", 14)` is the only truth for this test.

**Test 3: large_file**, schema verification across block files.

```c
static uint8_t pat[8192];
for (int i = 0; i < 8192; i++) pat[i] = (uint8_t)(i & 0xFF);

T("write 8KB");
if (knotfs_write("data.bin", pat, 8192)) { FAIL("enqueue"); return; }
if (drive()) { FAIL("result"); return; } OK();

T("read & verify");
{ uint8_t v[8192];  uint32_t br;
  memset(v, 0, sizeof(v));
  if (knotfs_read("data.bin", v, 8192, 0, &br)) { FAIL("enqueue"); return; }
  if (drive()) { FAIL("result"); return; }
  if (br == 8192 && !memcmp(v, pat, 8192)) OK();
  else FAIL("br=%u match=%d", br, memcmp(v, pat, 8192) == 0); }
```

This pattern data `pat[i] = i & 0xFF` is clever because the value of each byte is its offset (modulo 256). After reading it back in this way and doing `memcmp`, any bit misalignment (such as a wrong write with an offset of 1 byte) will be discovered immediately. 8192 bytes = 2 whole blocks + 0 bytes. Just verify the correct handling of block boundaries.

**Test 4: partial_read**, the offset is not at the beginning of the block.

```c
T("read offset");
uint8_t buf[32];  uint32_t br;
memset(buf, 0, sizeof(buf));
if (knotfs_read("data.bin", buf, 32, 2000, &br)) { FAIL("enqueue"); return; }
if (drive()) { FAIL("result"); return; }
uint8_t exp[32];
for (int i = 0; i < 32; i++) exp[i] = (uint8_t)((2000 + i) & 0xFF);
if (br == 32 && !memcmp(buf, exp, 32)) OK(); else FAIL("br=%u", br);
```

offset=2000, which is not an integer multiple of 4096. The first block (block 0) is read at offsets 2000~2031. Just verify the `seg_s = max(rs, bs)` and `src_o = seg_s - bs` calculations in `ST_RD_COPY`.

**Test 5: overwrite**, verification of CoW atomicity.

```c
T("overwrite");
const char *n = "greet.txt";
const char *s = "This file has been replaced!";
uint32_t len = (uint32_t)strlen(s);
if (knotfs_write(n, s, len)) { FAIL("enqueue"); return; }
if (drive()) { FAIL("result"); return; }

char b[64];  uint32_t br;
if (knotfs_read(n, b, sizeof(b), 0, &br)) { FAIL("enqueue"); return; }
if (drive()) { FAIL("result"); return; }
if (br == len && !memcmp(b, s, len)) OK(); else FAIL("got='%s'", b);
```

greet.txt changes from "Hello, KnotFS!" to "This file has been replaced!" through CoW's "allocate new block + release old block + compact" complete link. If CoW fails, you will either see old content or corrupted content. Seeing the correct new content indicates that the CoW replacement result under the normal completion path is correct.

**Test 6: append**, verification of RMW.

```c
T("append");
const char *add = " (appended)";
uint32_t alen = (uint32_t)strlen(add);
if (knotfs_append("greet.txt", add, alen)) { FAIL("enqueue"); return; }
if (drive()) { FAIL("result"); return; }

char b[128];  uint32_t br;
if (knotfs_read("greet.txt", b, sizeof(b), 0, &br)) { FAIL("enqueue"); return; }
if (drive()) { FAIL("result"); return; }
const char *exp = "This file has been replaced! (appended)";
if (br == (uint32_t)strlen(exp) && !strcmp(b, exp)) OK();
else FAIL("got='%s'", b);
```

Append 11 bytes to the existing file, the last block of RMW. File changed from 28 characters to 39 characters. Verified the correct offset of `write_off` within the block, the correctness of `memcpy(tmp + write_off, s, n)`, and the data integrity after compaction.

**Test 7: list**, view the file directory.

```c
T("list");
knotfs_entry_t ents[8];  uint32_t n = 8;
knotfs_list(ents, &n);  drive();
printf("  %u files:\n", n);
for (uint32_t i = 0; i < n; i++)
    printf("    %-32s %u B\n", ents[i].name, ents[i].size);
if (n == 2) OK(); else FAIL("expected 2, got %u", n);
```

There are two files in the file system at this time: `greet.txt` (39 bytes) and `data.bin` (8192 bytes). The list traverses `sb.nodes[]`, skhipus the slot with size==0, and outputs the file name and size.

**Test 8: delete**, delete and verify the directory.

```c
T("delete data.bin");
if (knotfs_delete("data.bin")) { FAIL("enqueue"); return; }
if (drive()) { FAIL("result"); return; }
knotfs_entry_t e[8];  uint32_t n = 8;
knotfs_list(e, &n);  drive();
if (n == 1 && !strcmp(e[0].name, "greet.txt")) OK(); else FAIL("n=%u", n);
```

After deleting the 8192-byte data.bin, the list should only show greet.txt. It was verified that `memset(nd, 0, sizeof(knode_t))` cleared the entry correctly and free_bitmap correctly recycled 2 blocks.

**Test 9: nonexistent**, wrong path.

```c
T("read missing");
char b[32];  uint32_t br = 99;
knotfs_read("nope.bin", b, sizeof(b), 0, &br);  int r = drive();
if (r != 0) OK(); else FAIL("should fail, got br=%u", br);
```

Reading a file that does not exist should return a negative error code (-20: file not found). `br` is initialized to 99 and should remain 99 if the test passes (because the output parameters should not be modified when the operation fails).

**Test 10: stats**, spatial statistics.

```c
uint32_t tot, fre;
knotfs_stats(&tot, &fre);  drive();
printf("  total: %u  free: %u  used: %u\n", tot, fre, tot - fre);
T("stats");
if (tot == KNOTFS_DATA_BLKS && fre < tot) OK(); else FAIL("tot=%u free=%u", tot, fre);
```

Total data blocks 14, free blocks should be less than 14 (because greet.txt occupies blocks). This test doesn't care about specific numbers, it just verifies that the statistics function is working properly.

**Test 11: power_loss**, the core verification of this chapter.

```c
/* capture state before power-cycle */
knotfs_entry_t before[8];  uint32_t bn = 8;
knotfs_list(before, &bn);  drive();

char b64[64];  uint32_t br64;
knotfs_read("greet.txt", b64, sizeof(b64), 0, &br64);  drive();
printf("  Before reset: '%s'\n", b64);
printf("  Simulating MCU power-cycle (in-memory state lost, flash intact)...\n");

/* power-cycle */
power_cycle();

T("remount");
if (knotfs_mount()) { FAIL("enqueue"); return; }
if (drive()) { FAIL("result"); return; }
if (!knotfs_is_mounted()) { FAIL("not mounted"); return; }
OK();

knotfs_entry_t after[8];  uint32_t an = 8;
knotfs_list(after, &an);  drive();
printf("  After reset: %u files\n", an);

char a64[64];  uint32_t ar64;
knotfs_read("greet.txt", a64, sizeof(a64), 0, &ar64);  drive();
printf("  After reset: '%s'\n", a64);

T("data intact");
if (bn == an && ar64 == br64 && !strcmp(b64, a64)) OK();
else FAIL("before='%s' after='%s'", b64, a64);
```

This is the most critical test of the entire set of tests. It compares before and after "power off" (power_cycle):
- Are the number of files consistent (`bn == an`)?
- Are the file sizes consistent (`ar64 == br64`)?
- Are the file contents consistent (`!strcmp(b64, a64)`)?If all three are true, it means:
1. mount correctly selects a valid SB copy
2. SB compact/ is selected correctly. The data is still there after remounting; log replay is not actually triggered in the current life cycle.
3. The file content is intact

**Test 12: format_and_remount**, loop verification of formatting from scratch.

```c
/* fresh format */
power_cycle();
knotfs_format();  drive();
printf("  Fresh format done.\n");

T("mount fresh");
if (knotfs_mount()) { FAIL("enqueue"); return; }
if (drive()) { FAIL("result"); return; }
OK();

/* write a file and remount */
const char *msg = "Persistent content across boots.";
uint32_t mlen = (uint32_t)strlen(msg);
knotfs_write("boot.txt", msg, mlen);  drive();

power_cycle();

T("remount & verify");
if (knotfs_mount()) { FAIL("enqueue"); return; }
if (drive()) { FAIL("result"); return; }
char chk[64];  uint32_t cr;
memset(chk, 0, sizeof(chk));
knotfs_read("boot.txt", chk, sizeof(chk), 0, &cr);  drive();
if (cr == mlen && !memcmp(chk, msg, mlen)) OK();
else FAIL("cr=%u expected=%u '%.32s'", cr, mlen, chk);
```

format → mount → write → power_cycle → remount → verify. This is the complete "cold start" process. It verified the format's ability to create dual SBs from scratch, and that after a write on a new file system, it can still be restored correctly after a power outage and restart.

## What does the test cover and what does it not cover?

**Covered:**
- Normal paths to all APIs (format/mount/write/read/append/delete/list/stats)
- Wrong path (reading non-existent file)
- Boundary conditions (reading and writing across blocks, misaligned offsets, file size is exactly an integral multiple of the block size)
- Restart persistence (power_cycle ×3; only simulates a clean restart, does not inject midway power loss)
- Wear leveling (write allocates new blocks, wear_count is incremented)
- CRC32 check (implicit verification when mount selects SB)

**Not covered:**
- Scenario where Flash is full (there is no free block when writing, so -6 should be returned)
- Extreme case of file name conflict (create the 9th file after all 8 files are full)
- `KNOTFS_LOG_THRESHOLD` (214) trigger paths; this threshold is currently not enabled, and the upper limit of the memory Log buffer is 32
- Indirect blocks (not available in KnotFS)
- Garbage collection (KnotFS has no background GC)
- Flash write latency and timing on real hardware

## If you design

Try to answer: Under what circumstances will Test 11 (power_loss) fail?

Answer: There are two main possibilities. ① `compact` did not complete successfully. If the compact of write or append is only half written before power_cycle (`fdev_write` is triggered but ticks_left has not dropped to 0), then the new SB is incomplete. But drive() will wait until `knotfs_is_idle()` is true before returning, that is, all operations are completed. So as long as drive() returns 0, compact must have completed. ② The SB selection is wrong when mounting. If the sequence numbers of the two SBs are equal and the contents are different (this may occur when the format's ST_FMT_WR_SB1 is powered off when half of it is written), the mount will select the first SB that passes the verification. However, the test process of KnotFS ensures that power_cycle occurs only after drive() is completed, so the sequence number must be correct.
